# nanoc_client

Python client for the **NanoC** computer running inside a Luanti/Minetest
server. Connects to the `nanoc_mod` over TCP (optionally TLS) to act as an
external **terminal** and **source-level debugger**, in parallel to the game.

The wire contract is defined in the sibling repo
[`nanoc_lib`](../nanoc_lib) under `doc/protocol.md`. This client implements
protocol version **1** and validates it during the handshake.

## Install (development)

```bash
pip install -e .
```

## Usage

```bash
nanoc-client --host 127.0.0.1 --port 40000 --token <TOKEN>
# optional: --tls --server-hostname <name>
```

The token is generated by the mod per terminal/session and shown to the player
in-game. Commands: `state`, `attach`, `bp <line>`, `step`, `cont`, `vars`,
`bt`, `key <text>`, `help`.

## Testing (no Luanti needed)

A mock server speaks the same protocol:

```bash
python -m nanoc_client.mock_server --port 40000 --token secret
python -m nanoc_client.cli --port 40000 --token secret
```

Unit tests:

```bash
python -m unittest discover -s tests
```

## Debugging from VS Code

This repo ships a minimal debugger extension (`vscode/nanoc-debug`) that
starts the `nanoc-dap` adapter and adds syntax highlighting for `.nanoc`
files (`.nc` is accepted as an alias).

Install (build a VSIX, no `vsce` needed), then restart VS Code:

```bash
~/Projekte/nanoc_client/vscode/build-vsix.sh
code --install-extension ~/Projekte/nanoc_client/vscode/nanoc-debug.vsix
```

Open the matching source file locally and add a `launch.json` configuration:

```json
{
  "type": "nanoc",
  "request": "attach",
  "name": "NanoC",
  "host": "127.0.0.1",
  "port": 41100,
  "token": "<TOKEN from the controller>",
  "source": "${file}",
  "program": "${file}",
  "upload": true
}
```

Start with F5: breakpoints, stepping, call stack, Globals/Locals and `printf`
output (Debug Console) all work. While attached, **NanoC: Upload Program to
Controller** (Ctrl+Alt+U) pushes the active editor to the controller
(+recompile), and **NanoC: Download Program from Controller** opens the
controller's program. `.nanoc` files (`.nc` alias) are also linted on save
(via the
local `nanoc-check`); problems appear in the Problems panel and jump to the
line on click (command **NanoC: Check Program (lint)**). Other DAP clients
(nvim-dap, Emacs dap-mode) can use the `nanoc-dap` executable directly.

## Scriptable CLI (`nanoc`)

Non-interactive commands, useful for scripts and AI agents (OpenCode, Claude,
…):

```bash
nanoc check app.nanoc                    # local lint (file:line: error)
nanoc push  app.nanoc --token T          # upload + compile (errors on stderr)
nanoc run   --token T                    # resume the controller
nanoc stop  --token T                    # halt (pause)
nanoc read  --token T --seconds 3        # print terminal output for 3 s
nanoc exec  app.nanoc --token T --seconds 3   # push + run + read (one call)
nanoc scan  --token T --radius 8              # TA4 techage topology as JSON
nanoc catalog --token T                       # Beduino topic catalog as JSON
```

Connection flags: `--host` (127.0.0.1), `--port` (41100), `--token` (from the
controller form), `--tls`. `nanoc exec` is the one-shot loop for automation:
write → exec → read output → improve.

## MCP server (`nanoc-mcp`)

Exposes the bridge to AI clients (Claude Desktop, OpenCode, …) as MCP tools:

`nanoc_scan`, `nanoc_check`, `nanoc_push`, `nanoc_program_get`, `nanoc_run`,
`nanoc_stop`, `nanoc_read`, `nanoc_exec`.

Connection defaults come from the environment (`NANOC_HOST`, `NANOC_PORT`,
`NANOC_TOKEN`, `NANOC_TLS`) or per tool call.

Claude Desktop (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "nanoc": {
      "command": "nanoc-mcp",
      "env": { "NANOC_PORT": "41100", "NANOC_TOKEN": "<TOKEN>" }
    }
  }
}
```

OpenCode (`opencode.json`, adjust to your version):

```json
{
  "mcp": {
    "nanoc": {
      "type": "local",
      "command": ["nanoc-mcp"],
      "environment": { "NANOC_PORT": "41100", "NANOC_TOKEN": "<TOKEN>" },
      "enabled": true
    }
  }
}
```

Typical AI loop: `nanoc_scan` → reason about the graph → `nanoc_exec`
(push+run+read) → refine.

## Focus

Only one client may debug a controller at a time. The first `attach` owns it;
other clients stay terminal viewers (they receive output) and get `DENIED` for
control commands. `detach` or disconnect releases the focus.

## Status

- `protocol.py` – framing, handshake, debug command vocabulary (protocol v1)
- `client.py` – blocking TCP/TLS client
- `cli.py` – interactive CLI with a reader thread
- `mock_server.py` – mock server for client testing
- `dap.py` – Debug Adapter Protocol server (`nanoc-dap`) for editors

A curses TUI can still be built on the same core later.
The Luanti-side bridge is `nanoc_mod/src/bridge.lua`.
